## 3. Concepts

| Term | Meaning |
|---|---|
| **Country pack** | All statutory content for one country (India first). A legal entity uses its country's pack (P01) |
| **Statute** | One law area inside a pack: `IN.PT`, `IN.PF`, `IN.ESI`, `IN.LWF`, `IN.MW`, `IN.TDS`, `IN.BONUS`, `IN.GRATUITY`, `IN.FACTORIES`, `IN.LEAVE`, `IN.POSH`, `IN.WAGES`, `IN.APPRENTICE`, `IN.SUBSISTENCE`, `IN.REGISTERS`, `IN.CLRA`, `IN.EC` (J6), `IN.CAL`; Labour Code statutes `IN.WAGES-CODE`, `IN.SS-CODE`, `IN.OSH`, `IN.IR` (C1, §4.7) |
| **Advisory** (B17) | A curated labour-law update (new law, amendment, notification, circular, court ruling, commencement of a Code) with a plain impact note; it may or may not lead to a rule-set change |
| **Rule set** | A versioned set of values for a statute + jurisdiction (e.g. PT · Karnataka), valid from an effective date |
| **Law version** (C1 / C2) | The enactment a rule set implements, chosen by the period date: old Act vs Labour Code for the labour statutes (§4.7); `IT-1961` vs `IT-2025` for `IN.TDS` (§4.8) |
| **Transitional rule set** (C1) | Rules made under an old Act that continue because the central or state government has not yet notified its rules under a Code; flagged to tenants until replaced |
| **Rule table shapes** | *Rate* (percent + ceiling + rounding), *Slab* (range → amount, with conditions such as gender, month, age), *List* (sections, cities, categories with limits), *Calendar* (due-date rules) |
| **Calculator** | Versioned code for logic too complex for tables (income tax projection), fed by rule-set values; each version pinned to golden test cases |
| **Legal option** | A choice the law leaves to the employer (e.g. PF on actual wage vs ceiling). Tenants choose these; they never change rates |
| **Coverage threshold (J1)** | A dated headcount threshold that makes a statute or duty apply to an establishment / entity (ESI 10+, PF 20+ with "once covered always covered", gratuity 10+, bonus 20+, POSH IC 10+, standing orders 300 under the IR Code, grievance redressal committee 20+, crèche 50+; verify each against the Codes and state rules). Stored as a `coverage` rule set per statute; the tenant's headcount is evaluated against it |
| **Special-case wage rules (V1, V6, J4, R5, R8)** | Piece-rate minimum-wage guarantee and OT basis, tips / service-charge wage and tax treatment, check-off, lay-off compensation, VRS exemption, the ELI scheme and the ESI PwD wage ceiling are dated rule-set parameters like any other; company policy above them comes from labelled starter templates (D17), the law is the floor |

## 4. Design

### 4.1 Storage (platform reference data)
- Rule sets live in a **platform schema**, not tenant tables: they are shared, read-only for all tenants, and have **no `organization_id`**. This is the documented exception to YX-ORG-14; the CI check whitelists only the `statutory` schema and platform catalogue tables (e.g. P09 standard metric definitions). Tenant custom rows always carry `organization_id`.
- Each rule set has:
  - `pack`, `statute`, `jurisdiction` (country / state / zone);
  - `valid_from`, `valid_to`;
  - `version`, `status` (draft / in review / published / withdrawn);
  - typed `payload`;
  - **`source`** (gazette notification / circular / URL, with a copy stored as a document);
  - `published_by`, `reviewed_by`, `published_at`, `change_note`.
- Tables are validated by a schema per shape (e.g. slabs contiguous and non-overlapping; PT annual total ≤ ₹2,500; rates between 0 and 100 %).

### 4.2 Evaluation
- A small typed **rule evaluator** handles the table shapes: slab lookup with inclusive bounds, rate × base with ceiling, rounding per statute, conditions (gender, month, age band, disability, half-year period).
- **No arbitrary code in data.**
- **Income tax / TDS** uses a **versioned calculator per financial year** (parameters from rule sets). A new FY's rules = new parameters, and a new calculator version only if the formula itself changes.
- Every evaluation records **which rule-set version** it used. Payroll stores these references with its inputs on `payslips` / `payslip_lines` (rule-pack version; M03 §4, P06 YX-HIS-09), so any payslip can be reproduced and explained ("PT Karnataka v2027-04 slab ₹25,001+").

### 4.3 Publishing workflow (YukthiX internal)
```
YukthiX compliance owner drafts change (source attached)
 → automatic checks (shape validation, golden test cases per statute)
 → second-person review (maker ≠ checker)
 → publish with effective date (future or past)
 → tenants notified (P04) with impact summary
```
- **Future-dated** publishes apply automatically when their date arrives (P06 semantics).
- **Past-dated** publishes (government notifies late): YukthiX flags affected tenants' processed payrolls and creates an **arrears proposal** (Q4).
- **Withdraw / fix:** a bad rule set is withdrawn by a new version; nothing is edited in place.

### 4.3a Labour-law advisory feed (B17)
Not every legal change is a rate. Tenants also need to know about new registers, licence rules, court rulings, Code commencements and filing-portal changes.
- **Curated by YukthiX** (compliance owner drafts, second person reviews, the partner CA firm contributes; same maker ≠ checker as §4.3), per **statute and state**, with source link and stored copy.
- **Each advisory:** title; statute(s); jurisdictions; published / effective dates; status (proposed / notified / in force / withdrawn); plain summary; **impact note** (who is affected, what changes, action needed, deadline); severity (info / action / urgent); links to the **rule-set versions** it caused (and each rule-set change links back), and to affected modules (e.g. M13 for a CLRA change).
- **Targeting:** shown to the **compliance owner**, HR Admin and Payroll Admin of tenants whose entities / locations are in the jurisdictions (from P01 registrations); an employee-facing summary only when employees are directly affected.
- **Delivery:** in-app feed *Compliance › Labour-law updates* (filter by state / statute), weekly email digest, immediate notice for urgent ones (P04); each tenant can mark an advisory **reviewed** with a note and optionally create a task; a public version feeds the public "statutory updates" log (Q5).
- **Cost:** curated by YukthiX, no third-party per-use cost → included (D18).

### 4.4 Tenant view and choices
- **Settings › Statutory rules** (read-only): current rules per statute and state for the tenant's entities and locations, with version history, source links and upcoming changes.
- **Legal options** (per legal entity, P01 settings): PF on actual wage or ceiling; employer share on actual wage; PT registration states; LWF applicability; bonus % (within 8.33–20 %); gratuity provisioning method.
- **No tenant overrides of rates** (Q1).

### 4.5 Checks powered by the pack
- **Minimum wage check:** each employee's wage vs the applicable minimum = max(state rate for location, zone, skill category, schedule; national floor wage) (YX-STAT-22), at payroll pre-flight and on salary changes. Blocking or warning per Q-level policy in module 03.
- **Bonus eligibility and calculation**, **gratuity eligibility and provision** (incl. fixed-term pro-rata after 1 year), **Code wage-definition add-back** (YX-STAT-21), retrenchment and re-skilling fund amounts and the IR / OSH thresholds (YX-STAT-23): exposed to payroll/lifecycle.
- **Compliance calendar:** due dates per entity from its registrations → P04 reminders and module 04's monthly statutory checklist; transitional rule sets show "state rules pending notification" per state (§4.7).
- **Estimated penalty:** for an item due or overdue, the calendar and the M03 statutory hub show an estimated interest / fee / damages figure from the statute's penalty parameters (§1), labelled "estimate", with the rule version (YX-STAT-14).

- Adding a country = a new pack + calculators + golden tests, with no change to modules that consume rules through the evaluator API.

### 4.7 Labour Codes and transition (C1)
The Code on Wages 2019, the Code on Social Security 2020, the OSH Code 2020 and the IR Code 2020 are **in force since 21 Nov 2025**. They are enforced law in the pack, not "verify status" items.
- **Code statutes:** `IN.WAGES-CODE` (wage definition and 50 % add-back, national floor wage, wages on exit within 2 working days, deduction limits), `IN.SS-CODE` (gratuity incl. fixed-term pro-rata after 1 year, PF / ESI / maternity chapters), `IN.OSH` (appointment letter for every worker, annual health check-up for workers 40+ where prescribed, women's night-shift consent and safeguards, contract-labour thresholds), `IN.IR` (retrenchment compensation, notice / pay in lieu, Worker Re-skilling Fund, lay-off / retrenchment / closure permission at 300+ workers, standing orders at 300+, grievance redressal committee at 20+). Each has rule sets **valid from 2025-11-21**.
- **Subject statutes keep their keys** (`IN.MW`, `IN.BONUS`, `IN.GRATUITY`, `IN.WAGES`, `IN.PF`, `IN.ESI`, `IN.LEAVE`, `IN.FACTORIES`, `IN.CLRA`, `IN.REGISTERS`, `IN.EC`), so no module changes: the old-Act version ends on 2025-11-20 and a new version citing the Code is valid from 2025-11-21.
- **Transition rule:**
  - a period **ending before 21 Nov 2025** uses the old Acts;
  - a period **straddling** the date is **split by days into P06 segments** (e.g. 1–20 Nov old Acts, 21–30 Nov Codes) unless a rule set states another basis (e.g. rules tied to an event date, such as the exit date for wages on exit or the retrenchment date);
  - where the central or a state government **has not yet notified its rules** under a Code, the existing rules under the old Act continue as a **transitional rule set** (`transitional = true`, source cited); Settings › Statutory rules and the compliance calendar show "state rules pending notification" for that state and statute; when the rules are notified, a new version replaces it (a past-dated one follows Q4, arrears proposal).
- **Code duties outside payroll** are exposed through the evaluator as thresholds and findings, never hard-coded: appointment letter for every worker (M01 joining check; APX-F #6), grievance redressal committee at 20+ workers (M08), standing orders at 300+ workers, health check-up due per worker aged 40+ (calendar item where prescribed), women's night-shift consent and safeguards (M02 roster rules, owned by M02). YX-STAT-20…23.

### 4.8 Income-tax law version (C2)
The **Income-tax Act 2025 is in force from 1 Apr 2026** and replaces the Income-tax Act 1961; "**tax year**" replaces previous year / assessment year. Sections are renumbered and forms renamed.
- **Law-version dimension:** every `IN.TDS` rule set, calculator version, form definition and calendar rule carries `law_version` = `IT-1961` or `IT-2025`. The period date picks it: periods and returns **up to the tax year ending 31 Mar 2026** use `IT-1961` (e.g. the Q4 FY 2025-26 24Q and the Form 16 / 16A issued in 2026, and any later correction of those quarters); periods **from 1 Apr 2026** use `IT-2025`.
- **Forms:**

| Purpose | 1961 Act (periods up to 31 Mar 2026) | Income-tax Act 2025 (from 1 Apr 2026) |
|---|---|---|
| Salary TDS certificate | Form 16 | **Form 130** |
| Non-salary TDS certificate | Form 16A | **Form 131** |
| Quarterly TDS return, salary | 24Q | **Form 138** |
| Quarterly TDS return, non-salary (residents) | 26Q | **Form 140** |
| Quarterly TDS return, non-residents | 27Q | **Form 144** |
| No-deduction self-declaration | 15G / 15H | **Form 121** |
| Employee investment / claims declaration | Form 12BB | Form 12BB successor (verify number) |
| Annual tax statement | Form 26AS / AIS | Same concept (verify name) |

- **Section cross-walk** (`law_crosswalk`, maker ≠ checker as §4.3): modules refer to stable subject keys; the section label shown on screens, files and forms comes from the cross-walk for the period's law version. New section numbers are **not invented**: the compliance owner fills each row from the notified Act, and an `IT-2025` rule set that cites a subject whose row is still unfilled **fails validation** (YX-STAT-24).

| Subject | 1961 Act | Income-tax Act 2025 |
|---|---|---|
| TDS on salary | s.192 | Cross-walk to be filled by compliance owner from the notified Act |
| TDS on contract work | s.194C | Cross-walk to be filled by compliance owner from the notified Act |
| TDS on professional / technical fees | s.194J (a) / (b) | Cross-walk to be filled by compliance owner from the notified Act |
| Higher rate without PAN / inoperative PAN | s.206AA | Cross-walk to be filled by compliance owner from the notified Act |
| Leave-encashment exemption | s.10(10AA) | Cross-walk to be filled by compliance owner from the notified Act |
| Rebate | s.87A | Cross-walk to be filled by compliance owner from the notified Act |
| New (default) tax regime | s.115BAC | Cross-walk to be filled by compliance owner from the notified Act |

  Other references used in the design (e.g. s.197, s.201(1A), s.234E, s.271H, s.89(1), s.80C / 80D / 24(b), Forms 12B / 12BA / 10E / 10F) are added as cross-walk rows the same way before the `IT-2025` rule sets that use them are published.
- **Old-form generators and templates stay** for periods up to 31 Mar 2026 (APX-F #76 / #78 / #79), including correction returns for those quarters.
