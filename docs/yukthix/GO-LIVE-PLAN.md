## 9. Summary for the founder

The product is largely built. What stands between us and the first paying customer is mostly not code. It is **people, paperwork and hosting**:

- **People.** We need a named compliance owner and a CA firm. Every statutory number (PF, ESI, PT, LWF, minimum wages, TDS) is still marked "verify", and the product will refuse to use those numbers in production until two people sign them off. This is the slowest item, so it should start this week.
- **Hosting.** There is no production environment yet. The engineering team must choose the cloud setup and then build it: backups we have actually restored, a disaster-recovery copy in a second Indian region, monitoring with someone on call, and secrets kept in a vault. That is several weeks of work.
- **Security.** Salary and bank data need their own per-company encryption keys, and we need a one-click "lock everything down" button for a breach. After that, an outside firm tests us before payroll goes live.
- **Code.** One real fix is known: locking a month's attendance does everything in one 5-second database step, which will fail for a large company. It is a medium-sized fix, followed by a load test. The other open choices can mostly be switched off for the pilot.
- **Partners.** Only three are needed for the pilot: the pilot company's bank file format, Protean's FVU instructions (until then we file by hand), and the e-invoice QR keys. eSign, background checks, penny-drop, earned-wage access, the filing partner, card feeds, travel and a paid FX feed can all wait until after the pilot.
- **The pilot itself.** Pick one company in one or two states, sign the contract and data agreement, load their data, and run the first month **side by side with their current payroll** before any real salary is paid from YukthiX.

Rough timeline if the compliance owner, the CA and the hosting work all start now: about **8–12 weeks** to a pilot parallel run, set mostly by the CA sign-offs and the pen test, not by the code.
