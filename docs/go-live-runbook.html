If something goes wrong — signature reference

What the candidate seesLikely causeWhat it means / action
Plain, unstyled page Web assets not served The build-time guard makes this unlikely now. If it appears: the web service needs a restart — flag me, don't guess.
Code question stuck on “Loading…” Editor asset blocked Should be fixed (Monaco is self-hosted). Check /monaco/vs/loader.js returns 200 from the office network — if not, the firewall is blocking the app's own origin, which is a network issue, not the app.
Webcam won't start / proctoring stuck MediaPipe asset blocked Should be fixed (self-hosted). Confirm /mediapipe/wasm/… and the model return 200. Also check the candidate actually granted camera permission.
“The server is busier than usual… try again” Brief overload (503) Retry-able and the app auto-retries. At a staggered pace you should see essentially none. A cluster of these means real load — tell me, don't restart.
“Too many requests” (429) Rate limit hit Limits are per-candidate now, so a normal candidate won't hit this. If one does, their client is likely stuck in a loop — have them hard-refresh.
“Can't open this invitation” Token invalid / used / expired Check that specific invitation in the recruiter console — revoked, already redeemed on another device, or past its window. Re-issue if needed.
Logged out unexpectedly Stale tab / expired session One Ctrl+Shift+R and re-login fixes it. Widespread occurrence only happens if a deploy slipped through the freeze — which is why the freeze matters.

Emergency reference

First move
Message me. I'll run the health check and tail logs to locate it fast — faster than restarting blind.
Golden rule
Don't panic-deploy or panic-restart. Every fix mid-exam risks more than the symptom. Diagnose first.
Known revert
The connection-pool change has a saved backup on the server (.env.bak_…); it can be reverted in one step if ever needed. It won't be, at this load.
Server access note
SSH to the VM is occasionally slow to connect (background bot traffic on port 22 — harmless, can't get in). If I go quiet for a minute during an intervention, that's why; I retry automatically.
Capacity headroom
If load ever spikes beyond plan, the database (GP_Gen5_2) and VM can be scaled up in minutes with no data migration — but at a 15-min staggered start this is not expected.

Why you're in good shape

At your staggered pace, arrivals peak around ~2 logins/second — a tiny fraction of capacity. With all ~1000 candidates mid-exam at once, the database sits near 0% CPU and the app uses roughly 20% of one core.

The database has 200 worker slots against at most 75 connections the app can open. That's the margin behind “no upgrade needed.”

The single remaining unknown is your office firewall — which is exactly what item 1, the dry run, exists to close.
