# WhatsApp Candidate Messaging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A WhatsApp candidate-messaging channel mirroring the email/SMS channel (manual + templates + stage-triggered + separate opt-out), built provider-pluggable from day one (Twilio WhatsApp + generic HTTP), inert-but-honest without config, secrets encrypted + never returned.

**Architecture:** New `Organization` (whatsappEnabled/whatsappProvider/whatsappConfigEncrypted) + `Candidate` (whatsappOptedOutAt) columns + `CandidateWhatsapp` & `CandidateWhatsappTemplate` RLS tables. A `WhatsappProviderAdapter` registry (Twilio WhatsApp + generic HTTP) behind a `WhatsappService.send` seam; a reusable SSRF guard in `common/ssrf.ts`. `CandidateWhatsappService.sendWhatsapp` + templates + config controller (secret-strip GET / merge PUT + catalog) + a fail-open trigger hook beside the email hook in `patchEntry`. Web: dynamic config card + templates editor + drawer send/history/opt-out + stage prompt.

**Tech Stack:** NestJS + Prisma (SQL Server), Next.js (apps/web), `@exam-platform/shared` (OrgSecretsCryptoService, TenantPrismaService, AuditService), Jest. Twilio + HTTP via global `fetch` (no new dep).

**Spec:** docs/superpowers/specs/2026-09-09-whatsapp-design.md

**Base:** off `main @ 9359b5e2`, independent (no dependency on candidate-sms / sms-providers).

## Global Constraints

- Config reads/writes on the non-RLS `organization` row (as the email/SMTP config does). New tenant tables ⇒ paired `_rls` (290001). Additive Org/Candidate columns ⇒ NONE. Migrations `20260909290000_whatsapp` + `20260909290001_whatsapp_rls`, after ALL parked siblings (210000–280000). **No seed.**
- **No new npm dependency** (Twilio + HTTP via global `fetch`). **NEVER `npm install`/`ci`/`update`.** Only Task 1 runs `prisma migrate deploy` / `prisma generate`.
- All provider secrets encrypted via `OrgSecretsCryptoService` inside the JSON blob; NEVER returned by any endpoint; NEVER logged.
- The provider NEVER fabricates delivery — deliverable gate. HTTP adapter SSRF guard mandatory at BOTH save-time (validateConfig) AND runtime (`redirect:'manual'` + re-validate the final post-substitution URL).
- `PermissionsGuard` handler-only → `@RequirePermissions` per method. Web cannot import `@exam-platform/shared` VALUES at runtime; no `ui-v2` barrel import in new web files.
- Do NOT change existing email-trigger / candidate flows; WhatsApp additions are additive + fail-open.
- Every commit verifies `git branch --show-current` == `feat/whatsapp` in the same command.
